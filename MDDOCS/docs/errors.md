# :material-alert-outline: کدهای پاسخ و خطا

پاسخ‌های CITIBIG API به دو لایه تقسیم می‌شوند: پاسخ **دروازه** (مشکلات احراز هویت یا مسیر) و پاسخ **سرویس** (نتیجهٔ خود سرویس). طبق پیشوند مسیر هر خانواده، قالب پاسخ سرویس متفاوت است.

## خطاهای دروازه (همهٔ سرویس‌ها)

| HTTP | پاسخ | معنی | اقدام |
|---|---|---|---|
| 401 | `{"message":"Missing API key in request"}` | هدر apikey ارسال نشده | افزودن هدر `apikey` |
| 401 | `{"message":"Invalid API key in request"}` | کلید نامعتبر | بررسی مقدار هدر |
| 404 | — | مسیر اشتباه | مطابق [مرجع سرویس‌ها](services/identity.md) |
| 400 | بسته به سرویس | ورودی ناقص یا نامعتبر | بررسی فیلدهای الزامی |

## خانوادهٔ `/apiir/` — قالب wrapper

```json
{ "data": {...}, "success": true, "code": 0, "message": "درخواست شما با موفقیت انجام شد" }
```

| code | معنی | اقدام |
|—|—|—|
| 0 | موفق | `data` را بخوانید |
| 400 | ورودی ناقص/نامعتبر | متن `message` نام فیلد را اعلام می‌کند |
| 401 | کلید سرویس محدود/نامعتبر | از CITIBIG پیگیری کنید |
| `tokenStatus:false` | کلید محدود شده | از CITIBIG پیگیری کنید |

## خانوادهٔ `/ehraz/` — پاسخ مستقیم

- **موفق:** آبجکت داده مستقیم (بدون wrapper)
- **خطا:** `{"code": "...", "message": "..."}`

| code | معنی | اقدام |
|---|---|---|
| 0 | پردازش شده؛ ساختار نتیجه را بررسی کنید | — |
| 1 / 2 | بدنهٔ درخواست ناقص یا خالی | فیلدهای الزامی را ارسال کنید |
| 3 / 5 | سرویس برای حساب فعال نیست | از CITIBIG پیگیری کنید |
| 6 | موجودی کافی نیست | از CITIBIG پیگیری کنید |
| 7 | درخواست باید HTTPS باشد | — |
| 9 | سرویس موقتاً پاسخگو نیست | تلاش مجدد |
| 401 | توکن/دسترسی نامعتبر | از CITIBIG پیگیری کنید |
| 27 | مسیر قابل استفاده نیست | مسیر را مطابق مرجع بررسی کنید |

## خانوادهٔ `/services/` — قالب wrapper

```json
{ "result": 1, "response_body": { ... } }
```

| result | معنی | اقدام |
|---|---|---|
| 1 | موفق | `response_body` را بخوانید |
| 4 | درخواست نامعتبر | فیلدهای ورودی را بررسی کنید |
| 5 | خطای سمت سرویس | تلاش مجدد؛ در تکرار از CITIBIG پیگیری کنید |
| 6 | خطای ورودی / عدم دسترسی | ورودی را مطابق مرجع بررسی کنید |

!!! note "هدر Host برای خانوادهٔ `/services/`"

    درخواست‌های این خانواده باید هدر `Host: service.zohal.io` را نیز داشته باشند؛ در غیر این صورت پاسخ 400 می‌گیرید.

```bash
curl -X POST "http://2.144.22.190:9080/services/inquiry/shahkar" \
  -H "apikey: YOUR_API_KEY" \
  -H "Host: service.zohal.io" \
  -H "Content-Type: application/json" \
  -d '{"nationalCode":"0012345678","mobile":"09121234567"}'
```

## عیب‌یابی سریع

- **401 با پیام دروازه** → احراز هویت؛ بخش [احراز هویت](authentication.md)
- **400 با ذکر نام فیلد** → ورودی ناقص؛ جدول ورودی‌های همان سرویس در مرجع
- **404** → مسیر؛ دقیقاً همان مسیر جدول مرجع را فراخوانی کنید
- **سایر کدها** → قالب خانوادهٔ همان سرویس (بخش‌های بالا)
MDEOF
